## 2. 11 列各自是什么（逐列给证据）

先列 `.mob [ability category]` 的官方词条（`tagdict.sqlite` 的 `tags` 表，`ext='mob', tag='ability category'`）：

> `[HP MAX]`为怪物血量 | `[EQUIPMENT_PHYSICAL_ATTACK]`为物理攻击 | `[EQUIPMENT_PHYSICAL_DEFENSE]`为物理防御 | `[EQUIPMENT_MAGICAL_ATTACK]`为魔法攻击 | `[EQUIPMENT_MAGICAL_DEFENSE]`为魔法防御

**只有 5 个键**。这就是基表 10 个数值列要装的 5 个属性。

| 列 | 语义 | 取值(Lv1→Lv100) | 证据 | 等级 |
|---|---|---|---|---|
| col0 | 等级 | 1 → 100 | col0 恒等于行号+1，无例外 | **实证** |
| col1 / col3 | **?（常量 30）** | 30 → 30 | 100 行恒 30；无任何 `[ability category]` 键能对上「不随等级变」的量 | **待验证** |
| col2 / col4 | **物理防御 / 魔法防御 基值** | 0 → 1733 | 见下方 (b)(c) | **推断（中）** |
| col5 / col6 | **HP 基值** | 50 → 38549 | 见下方 (a) | **实证** |
| col7 / col9 | **物理攻击 / 魔法攻击 基值** | 2 → 497 | 见下方 (b) | **推断（强）** |
| col8 / col10 | **经验值** | 150 → 15000 | 见下方 (d) | **推断（强）** |

### (a) HP = col5 —— 排除法，实证

HP 是唯一一个「不能为 0、且必须大幅增长」的量。四列候选：

- col2 从 **0** 起（Lv1 = 0）。HP 为 0 的怪不存在 → 排除。
- col7 从 **2** 起，Lv100 才 497。Lv1 怪 2 血、Lv100 怪 497 血，跨 100 级只涨 248 倍且绝对值荒谬 → 排除。
- col8 是 **150 × 等级** 的完美线性（150/300/450/…/15000，见 (d)）——完美线性的量几乎不可能是 HP 曲线 → 排除。
- col5：50 → 38549，跨 100 级涨 **771 倍**，单调、增速渐快（前 10 级 +24~+56，后 10 级 +390~+778），是典型的 HP 曲线。**只剩它**。

再用官方 `[champion]`/boss 的乘数上限交叉验算：全库 566 只怪的 `[HP MAX]` 乘数最大 **250000**（=2500×，raid boss）。`38549 × 2500 = 9640 万` HP —— 对 Lv100 团本 boss 是合理量级；若 HP 是 col8（15000×2500 = 3750 万）也说得通，但 col8 的「完美线性」把嫌疑排除。**判定：col5 = HP（实证级，靠排除法成立）。**

### (b) col7 = 攻击、col2 = 防御 —— 用乘数上限反推，推断（强）

乘数分布是这条的关键（下面 §3 会证明乘数是「百分比」）。全库 567 只怪的 `[ability category]` 统计：

| 键 | 样本 | 最小 | 最大 | 众数 |
|---|---|---|---|---|
| `[HP MAX]` | 566 | 0 | **250000** | 200（43 次）、100（39 次） |
| `[EQUIPMENT_PHYSICAL_ATTACK]` | 527 | 0 | **400** | **100（221 次）** |
| `[EQUIPMENT_PHYSICAL_DEFENSE]` | 553 | 0 | **14735** | 100（279 次） |
| `[EQUIPMENT_MAGICAL_ATTACK]` | 527 | 0 | **430** | 100（217 次） |
| `[EQUIPMENT_MAGICAL_DEFENSE]` | 554 | 0 | **500000** | 100（202 次） |

**攻击乘数最大只到约 4 倍（400%），防御乘数可以到 147 倍（14735%）甚至 5000 倍。** 这是 DNF 的设计事实：怪物攻击力被刻意压在「打不死人」的量级，防御力则允许被拉到极高（靠伤害公式的分母吸收）。

于是：
- 若 col8（Lv100 = 15000）当攻击基值，×4 倍 = 6 万伤害/下。玩家 Lv100 血量在万级 → **一击必杀**，与「攻击乘数不超过 4 倍」的设计自相矛盾 → col8 不是攻击。
- col7（Lv100 = 497）当攻击基值，×4 = 1988；玩家 Lv100 HP 万级 → 十几下才死，与 DNF 普通怪「挠痒」的体感一致 → **col7 = 攻击（推断·强）**。
- 反过来，col2（0→1733）配 147 倍防御乘数 = 25 万防御，正好需要伤害公式的分母来消化 → **col2 = 防御（推断·中）**；col8（15000）配 147 倍 = 220 万，量级过头。

> 物理/魔法共用同一条基值列（col7 与 col9 恒等、col2 与 col4 恒等）：因为基表是「通用怪」的中性曲线，物理与魔法的差异全部由 `.mob` 的两个乘数分别控制。这解释了为什么 5 个属性只占 5 列而不是更多。

### (c) col2 的曲线长什么样（帮助实现者判断自己没读错）

`col2` 100 个值：`0, 5, 11, 17, 23, 29, 35, 42, 49, 56, 64, 72, 80, 88, 96, 105, 114, 123, 133, 143, 153, …(中略)…, 1703, 1733`。

一阶差从 +5 缓慢爬到 +30，**不是线性、也不是纯指数**（试过 `1733·(L/100)^1.5`、`a·L + b·L²` 都不精确拟合）→ 这是一张手调的曲线表，别试图用公式重算，直接查表。Lv1 = **0**（低级怪没有防御，这是刻意的：让 Lv1 玩家每一刀都打满）。

### (d) col8 = 经验 —— 完美线性，推断（强）

`col8 = 150 × level`，逐行验证 100/100 命中（150/300/450/600/750/900/1050/1200/1350/1500 … 15000）。

- 与 `character/exptable.tbl`（玩家升级经验 1000/2653/5543/…）**不是同一张表**，所以它不是玩家经验。
- 但它也不在 `[ability category]` 的 5 个键里 —— 说明基表除了 5 个乘数属性，还顺带存了「按等级给的经验」用于击杀结算（怪物的 `[ability category]` 没有 `[EXP]` 键，经验只能来自基表）。
- Lv1 怪 150 经验 / 升级需 1000 → **约 7 只升 1 级**，与「首切片打一趟洛蘭就升 1–2 级」的节奏吻合。

⚠️ 这是我**推断**的（没有官方词条直接写「col8 是经验」）。但它是 col8 唯一的合理解释；若实现后发现经验结算另有来源，把 col8 当「备用常量」即可，不影响战斗。

### (e) col1 / col3 = 常量 30 —— 待验证，但不挡实现

100 行恒 30，无法对应任何「随等级增长的属性」。可能是命中基数、暴击基数或抗性基数（`.mob` 里另有 `[dark resistance]`/`[light resistance]` 等逐怪字段，说明抗性不走基表）。**M3 直接忽略这两列**（乘数表里也没有对应键）。

## 3. 乘数怎么叠：`base × (乘数/100)`，不是 `base × (1 + 乘数/100)`

**结论：`实际值 = 基表值 × 乘数 / 100`。证据等级：实证。**

三条独立证据：

1. **算子与众数**（最强）：`.mob [ability category]` 的词法不是「键 值」，而是 **`[KEY] * 数值`** 三元组（实测 2,723 个 `*` vs 4 个 `+`）。四个防御/攻击键的**众数都是 100**（221/527、279/553、217/527、202/554 次），而 `0` 极少出现。若语义是 `×(1+v/100)`，中性值应是 **0**；实测众数是 100 → `×(100/100)=×1` 才是中性。**这是判定的核心。**
   ```
   [ability category]  [HP MAX] * 70  [EQUIPMENT_PHYSICAL_ATTACK] * 90  …
   ```
2. **`+` 算子的存在**：4 个样本用 `+`，说明系统支持「百分比乘」与「绝对加」两种算子；`*` 的数就是百分比。
3. **量级自洽**：`[HP MAX] * 70` 若解成 ×70 倍，Lv1 哥布林 = 50×70 = **3500** 血（玩家 Lv1 普攻 29.5 → 119 刀），荒谬；解成 ×0.70 = **35** 血 → 2 刀，与原作体感一致。

> 顺带修正一处「文档 vs 数据」的冲突：`.mob` 里 `[ability category]` 写成 `[HP MAX] * 70` 这种带算子的形式，**不是**「`[hp max]` 两个参数（最小/最大等级能力值）」的字段。**修正 `06-monster.md` §能力值表 那一条**：`.mob` 没有 `[hp max]` 绝对数值字段（我在 900 个 `.mob` 上扫过键名，`hp` 只出现在 `[hp regen rate]`），怪物血量**只能**由「基表行 × `[HP MAX]` 百分比」得到。

### 3.1 `[ability table]` 是「选哪张表」，不是「选哪一行」

官方词条：`[ability table]` 跟随的能力值表索引，**0=基本，1=召唤物，2=竞争地牢，默认 0**。

实测分布（900 个样本）：**无该标签 483 只**（=默认 0）、`1` 59 只（如 `casillas.mob` 召唤物）、`2` 16 只（`warroom_champion_hunter.mob`）、`3` 8 只（`chaos_alex.mob`）、显式 `0` 3 只。

→ **行号只由等级决定**（`row = level`），`[ability table]` 只决定去哪儿取行。首切片 12 只怪**全部没有 `[ability table]`**，一律读 `monsterbaseparameter.tbl`，不涉及 commonmonster/boss/named/summon 那几张 24 列 / 200 级的表。

## 4. 实现用常量表（直接抄进代码）

| 列号 | 语义 | 单位 | 状态 |

| 7 (=9) | 物理攻击 / 魔法攻击 基值 | 点 | 已定（推断，M3 可用） |
| 8 (=10) | 经验值（=150×等级） | 点 | 已定（推断） |
| — | `[HP MAX] * v` | 百分比，100=1.0× | **已定（实证）** |
| — | `[EQUIPMENT_*_ATTACK] * v` | 百分比 | 已定（实证） |
| — | `[EQUIPMENT_*_DEFENSE] * v` | 百分比 | 已定（实证） |

查找函数（伪代码）：

```
row   = table[level - 1]          # row = level，不是 level-1 下标之外再偏移
hp    = row[5]  * hpMaxPct   / 100
atk   = row[7]  * atkPct     / 100
def   = row[2]  * defPct     / 100
exp   = row[8]                    # 不受乘数影响（无对应键）
```

## 5. 一句结论（Lv1 基准）

**按此实现，Lv1 哥布林 HP = 50 × 70% = `35`；玩家 Lv1 普攻伤害 = `(7.5 角色物攻 + 22 破損的武士刀) × 100% − 0(防御) = 29`；35 / 29 → 需 2 刀。**
（上挑 Lv1 倍率 120% → 29.5×1.2 = `35.4`，正好一刀；说明基表 + 乘数 + 技能倍率三者的量级自洽。）
