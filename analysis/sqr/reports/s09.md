## 疑点（需要后续统一处理）

1. **常量的归属（已按更正后的规则处理，仍需后处理注意）**：本组这些常量不在 `SqrConsts`，已在**各自的 .gd 里就地 `const` 声明**（清单见上「反向核查」）。
   风险在于：同一个名字（如 `S_SPINCUTTER_RECALL`、`DS_APEND_GAUGE`、`PO_LIGHTNING_WALL_MOVE`）在**别的组**负责的 .gd 里也会被就地声明一次——各 .gd 是独立类，互不冲突；但只要后处理把这些名字补进 `SqrConsts`，所有就地声明就会变成 `already exists`，届时需要跑 `tools/sqr_dedupe_consts.py` 统一清理。
   `S_PO_ATCLT_*`（s07/s08）是同类问题。
2. **`po_spincutter` 的两处时间算法不一致**：`setCustomData_po_Spincutter` 用写死的 `term = 500 / hitCnt`，而召回分支 `setState_po_Spincutter` 用 `attackTime / hitCnt`（`attackTime = pAni.getDelaySum(false)`）；同一把武器两个阶段的多段间隔因此不同，疑似作者改代码残留。已保留原逻辑 + `# 【译注】` 标注。
3. **`lightningwall` 的静态数据第 2 项语义**：施法侧注释写「移动距离」，写进包时注释又写「目的地 x 坐标」；`po_lightningwall.nut` 那边收到后到底当距离还是当坐标，需要等该文件译完后对一下（本组不包含它）。
4. **`holong_light` 的 `x = -26` 被当绝对坐标**：目标搜索起点用 `sq_GetDistancePos(角色x, 朝向, -26)`（相对偏移，合理），但随后算射程时写成 `maxDistance = abs(activeObject.getXPos() - x)`，即拿**目标绝对 x 减去常量 -26**，而不是减去角色的 x；疑为把「相对偏移」误当「绝对坐标」，已加译注并保留原逻辑。
5. **`crystalattack` 的旧实现整段被注释**：其中用到 `SKILL_CRYSTALATTACK_EX`、「上方补 4 颗」的 `angles/xDistances` 表；现版本（计时事件）**完全没有强化被动分支**，等于该被动在当前逻辑下不生效，疑为改写时漏掉，需策划/后续版本确认。
6. **`fallingsoul` 与 `execution`（不在本组）高度重复**：两者都从 `ap_avenger_devilstrike` 读恶魔能量、都做「换算 → 挂附加体 → 扣能量」，差异只在技能 ID 与状态变化名；若后续要合并公共函数，这两处应一起改。
7. **`sq_GetSTATE()` 大小写**：`fallingsoul.nut` 用 `obj.sq_GetSTATE()`，其它文件普遍 `sq_GetState()`；`SqrScript` 桩按名字精确匹配，翻译版保留原拼写，运行时会走空实现并返回 null —— 需要宿主绑定层补一个别名，或在该文件保持原样由后处理统一（已在该文件加译注）。
8. **`creatormage_header` 的 `l_CHARGE_ON`**：小写字母 `l` 开头，与同表 `I_*` 系列（附加体槽位）风格不符，疑为 `I_CHARGE_ON` 的 OCR/输入笔误；按「禁改标识符」原样保留并标注。
