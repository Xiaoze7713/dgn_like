## 需要人看的点 / 疑点

1. **常量分两类处理（按 lead 的更正口径：本文件顶层定义的自己声明，别处定义的裸用）**：
   - **本组自己在顶层 `<-` 定义、且基类没有 → 已就地声明 `const`**（判断式 `grep -c "^const NAME " sqr_gd/sqr_consts.gd` 为 0）：
     `sqr_gd/character/atmage/darkchange/dark_change.gd:11-12` 的 `const SUB_STATE_DARK_CHANGE_READY := 0` / `const SUB_STATE_DARK_CHANGE_START := 1`，
     `sqr_gd/character/atmage/chainlightning/po_atchainlightningtarget.gd:10-11` 的 `const S_PO_ATCLT_0 := 10` / `const S_PO_ATCLT_1 := 11`。
     其余 10 个文件源码顶层没有任何 `<-` 声明（`grep -c "<-"` 全为 0）。
   - **定义在别组 .nut 顶层、基类没有 → 本组只裸引用（不能在文件里声明，否则别的文件也看不见）**，这 4 个需要有人补进 `SqrConsts`：
     `SL_DASH_MAGIC_ATK`（=8，`sqr_src_utf8/sqr/character/priest/avenger_common.nut:15`，被 `dashattack.gd` 用）、
     `STATE_SLOW_HEAL`（=0，`sqr_src_utf8/sqr/character/atmage/diehard/ap_atmage_diehard.nut:3`，被 `ap_atmage_diehardslowheal.gd` 用）、
     `SUB_STATE_ICEMAN_3`（=3）/ `SUB_STATE_ICEMAN_4`（=4，`sqr_src_utf8/sqr/character/atmage/iceman/iceman.nut:5-6`，被 `ap_aticemanmagiccircle.gd` 用）、
     `SUB_STATE_ATCHAINLIGHTNING_2`（=2，`sqr_src_utf8/sqr/character/atmage/chainlightning/chainlightning.nut:4`，被 `po_atchainlightningtarget.gd` 用）。
   补充事实：`grep -c "const SUB_STATE_" sqr_gd/sqr_consts.gd` 返回 **0**，整个 `SUB_STATE_*` 家族都没进基类；checker 不编译 GDScript，所以自检是绿的，**真编译前上面 4 个裸引用会 `Identifier not declared`**。
2. **`checkModuleType` 没有任何桩**：`ice_sword.gd` 的 `onKeyFrameFlag` 用它判 PVP（`MODULE_TYPE_PVP_TYPE` 常量本身在 `SqrConsts` 里有）。要么补一个返回 false 的桩，要么由宿主提供。
3. **`obj.sq_var` / `obj.timer_` 是"宿主成员"而不是方法调用**：`po_atchainlightningtarget.gd` 用 `obj.sq_var.push_obj_vector(...)`、`obj.timer_.setParameter(term, -1)`，`ap_atmage_diehardslowheal.gd` 用 `appendage.sq_var.get_timer_vector(0)`。这是照既有移植先例描的（`sqr_gd/character/atmage/crystalattack/po_crystalcore.gd:30` 的 `obj.sq_var.setInt(0, dmg)`、`sqr_gd/character/atmage/tundrasoul/ap_atmage_tundrasoul.gd:213` 的 `appendage.sq_var.get_timer_vector(0)`），**但运行时的 GDScript 对象是否真的暴露这两个属性，需要确认**：`sq_var` 应等价于 `obj.getVar()`（默认 var 组），`timer_` 应等价于"对象自带计时器"。若运行时不支持，这两处是最先崩的地方，替换方案是 `obj.getVar()` / `obj.getVar().get_timer_vector(0)`（后者需先 `push_timer_vector()`）。
4. **`po_atchainlightningtarget.gd:211` 的 `get_obj_vector_size(0)`**：同文件 118 行是不带参调用，这里多传了 0。已标 `# 【原文 bug】`，逻辑未改（若运行时按参数个数严格校验，这里会报错；按语义应改成 `get_obj_vector_size()`）。
5. **`ap_atmage_diehardslowheal.gd:66` 的空引用**：`sq_GetCNRDObjectToSQRCharacter(parentObj)` 之后直接 `sqrObj.getHp()`，没判空。同文件 `onSetHp` 里对同一个转换结果是判空的，说明作者知道它可能为空——**这一处是真 bug**，已标注未改。
6. **`fire_road.gd:41` / `dark_change.gd:55` 的 `SKILL_BROKENARROW` 残留**：两个技能的 `checkCommandEnable` 注释尾部都挂着另一句 `obj.sq_IsCommandEnable(SKILL_BROKENARROW);`。在注释里不影响执行，但如果有人据此"修正"成实际调用，会把两个技能都变成被弓箭技能放行。已标 bug。
7. **`dashattack.gd:140` 的槽位注释与用途不符**：2 号槽注释写「到达点」，实际存的是冲刺终点（起点 + 450）。`onEndState` 与阻塞判定都按"冲刺终点"用它，注释会影响后来人。已标 bug，未改。
8. **`ap_aticemanmagiccircle.gd` 是半成品**：`prepareDraw` 里 5 段"命中"只 `print(" hit")`，`sq_SendHitObjectPacket` 被注释掉，`h` 算了不用；`isEnd` 恒 false。冰人抓取的伤害实际上由别处（冰人技能脚本 / 抓取判定）产生，本附加体只管"按住状态"。若后续要补齐伤害，改点在 `sqr_gd/character/atmage/iceman/ap_aticemanmagiccircle.gd:162` 附近。
9. **两个附加体的 `isEnd` 都抄了同一句韩文注释**「어벤져 각성 변신의 끝부분」（复仇者觉醒变身的收尾部分）——`ap_aticemanmagiccircle.gd:216`、`ap_atmage_diehardslowheal.gd:216`，都与各自功能无关，且 `T` 取了不用。属复制粘贴残留，已标 bug。

    另有一处同函数内重复 `local skill_level`（`ice_sword`）→ 第二处改成直接赋值。除以上，**标识符 / 字符串 / 数字 / 循环边界全部与源码一致**。
