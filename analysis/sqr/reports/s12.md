## 需要人看的点

1. **阻塞全项目的基类问题（不在我的文件里，但必须有人修生成器）**：`sqr_gd/sqr_consts.gd` 由 `tools/sqr_consts.py` 从各 .nut 顶层抽常量，把 Squirrel 的**运行时值**当成了编译期 const：
   - `:1788` `const DEBUG := isDebugMode();` → `Parse Error: Function "isDebugMode()" not found in base self.` + `Assigned value for constant "DEBUG" isn't a constant expression.`；
   - `:1789` `const NULL := null;`；
   - `:2170` `const TEST_MODE_EXCUTION := DEBUG;` → `The constant type is being inferred from a Variant value, so it will be typed as Variant. (Warning treated as error.)`。
   后果是 `SqrConsts` 编译失败 → `SqrScript` `Could not resolve class` → **全项目每个 .gd 都 FAIL**，包括早已验过的 `chainlightning.gd`。建议生成器跳过 `DEBUG`/`NULL`（或写成 `var`），`TEST_MODE_EXCUTION` 直接给 `false`。我只在 `/tmp/sqrchk` 的副本里临时改掉了，仓库没动。
2. **文件内 const 的去向**：翻译时按任务说明「基类已有就别再声明」核对过，仍在本 .nut 顶层定义的 slot 先写了 `const`（`VI_SKL_0..9`、`BrokenArrow_state_0/1/2`、`SUB_STATE_ICEROAD_*`、`ENUM_ICE_CRASH_*`、`ENUM_AMP_SUBSTATE_*`、`TIMER_MULTI_SHOT_*`/`ENUM_MULTI_SHOT_SUBSTATE_*`/`ENUM_MAGIC_CANNON_SUBSTATE_*`、`SUBSTATE_PANDEMONIUM_EX_*`、`PEND_EX_*` 等，三十余个）。随后 lead 的后处理（`sqr_dedupe_consts.py`）把它们**全部搬进了 `sqr_consts.gd`**，并在原处换成说明注释——所以现在 12 个 .gd 里 `^const` 计数是 0，属预期状态。如果之后有人手动删掉基类那几段，这些文件会立刻 `Identifier ... not declared`（`sqr_check.py` 查不出来，只有真 Godot 会报）。
3. **原脚本 bug（保留原逻辑 + `# 【原文 bug】`）**

   - `passive_skill_priest.gd:59`：`sq_AppendAppendage` 的返回值没判空就用了。
   - `windpress.gd:25`：`print("b_useskill : %d" + b_useskill)` —— 格式化串用 `+` 拼值，`%d` 永远没被替换。
   - `pushout.gd:240`：关键帧里没判 `damager` 空就直接取身高。
   - `po_atbrokenarrow.gd:137`：`if(passiveState == 0)` 的分支永远不成立（状态从 10 起），死代码。
   - `multishot.gd:52`：原脚本把一整段注释又原样复制到了代码后面（重复块，保留成注释）。
4. **疑点（未改动，供确认）**
   - `po_windstorm.gd` 里 `initGetVarTimer` 被后处理加了 `xg.` 前缀：它在 `atmage_common.nut:307` 确实有 Squirrel 定义，所以归 globals 没错；但真机上它更像宿主内建（行为是往对象上挂计时器），如果宿主侧要按 `sq_*` 绑定实现，需要把桩移到 `SqrScript` 并在 `sqr_xref.py` 里排除，否则会变成 `xg.initGetVarTimer(self, obj, 2, term, -1)` 这个多传一个 `self` 的形状。
