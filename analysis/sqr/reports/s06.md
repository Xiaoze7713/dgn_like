## 需要人看的点（疑点 / 原脚本 bug 汇总）

1. **`var` 是 GDScript 声明关键字**：`ap_lightningwall.nut` 与 `po_iceareaicerain.nut` 各有 3 处
   `local var = obj.getVar();`，本组统一改成 `var sq_var = ...`，并在上一行留
   `# 原: local var = obj.getVar();` + `# 译: ...`（与先例 `sqr_gd/character/atmage/pieceofice/po_atpieceoficecore.gd:24-26` 一致）。
   其余 10 个文件没有这个问题（`po_atpieceofice.nut` 是 0 处）。
   → 后续组若遇到同样的写法，直接沿用 `sq_var`。
2. **计时通道不一致**（`ap_creatormage_guardian.nut`）：`onStart` 里 `appendage.setTimer(...)`/`timer_vector`
   与 `proc` 里 `appendage.getTimer()` 不是同一条通道，充能推进可能永远拿到 0。按原样保留并标疑点。
3. **参数不全的等级读取**：`wind_strike.nut` 的 `obj.sq_GetLevelData(2)` 只传 2 个参数（正常 3 个）；
   `atmagedashattack.nut` 在火/水/暗/光分支里 `sq_WriteWord(-25)`（Word 无符号 → 65511）。
   属性分支的 `power` 明显漏了同样的加算，属于「改了一半」的代码，已标 `# 【原文 bug】`。
4. **收包脚本缺失**：`24261`~`24265`、`23501` 在本次导出里没有对应的 po 脚本 / `pushPassiveObj` 注册，
   包位序只能靠命名规律猜（本组注释写成「应读」，没有断言）。移植时若这两个 ID 的 po 脚本到位，
   **必须回头核对位序**。
5. **变身判定用错常量**（`atmagedashattack.nut`）：把 `SKILL_ICE_ELEMENTAL_ATTACK`（冰属性攻击）的等级
   当作「已学变身（수인체）」，而真正相关的常量是 `SKILL_ELEMENTAL_CHANGE`。行为上等价于「学了冰属性攻击就吃加成」，
   与原意不符，已标疑点但**没改代码**。
6. **空操作 / 死代码**：`sq_SetCurrentAttackInfo(obj, sq_GetCurrentAttackInfo(obj))` 自赋值；
