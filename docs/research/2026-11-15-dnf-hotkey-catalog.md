# DNF 客户端键位动作表（官方数据）

- 期次：2026-11-15
- 作者：DSH（资源与行为研究）
- 状态：已确认（数据直接来自客户端，可复现）
- 关联任务：底部 HUD 与全局键位绑定

## 1. 问题与范围

新作需要一套「系统 / 角色 / 技能 / 聊天」四类的键盘绑定。要回答的是：
**DNF 客户端自己把「可绑定动作」定义成哪些、怎么分类**，而不是我们凭印象编一份清单。

范围：只取客户端的键位元数据（动作名、id、分类、左右列），不涉及默认键值以外的行为判断。

## 2. 方法与复现

```bash
# 1) 解内层 PVF（外层取钥见 docs/PVF-NEW-FORMAT-34.md）
python3 tools/pvf_new_extract.py --extract clientonly/hotkeysystem_ver3.co
# 2) 导出动作表到工程
python3 tools/extract_dnf_hotkeys.py     # → dnf_like/data/dnf_hotkeys.json
```

源文件：`Script.pvf:clientonly/hotkeysystem_ver3.co`（7,345 B，dtype=1 token 流）。
同族文件还有 `hotkeysystem.co`(2,640 B)、`hotkeysystem_ver2.co`(2,610 B)、
`hotkeysystemforcreator.co`、`gamepad/gamepadhotkeyinfo.co`。

## 3. 观察（可验证事实）

- **A1** 每条记录 6 个字段：`[key]` + 名称 + 动作 id（`I01`/`K02`/`C03`…）+ 分类 + 左右列 + 键位 + 类型。
- **A2** 分类只有四种：`system` / `character` / `dungeon` / `quickchat`，与客户端「键盘设置窗口」的
  四页签（系统 / 角色 / 技能 / 聊天快捷键）一一对应。
- **A3** 原始 207 条记录里，同一个动作 id 会按类型重复（`NormalType` / `CommonType` /
  `AradRoyalRumbleCommonType` / `CreatorType`）；按 id 去重后 **123 个动作**：
  系统 59 / 角色 27 / 技能 27 / 聊天 10。
- **A4** **键位字段全部为空**——默认键不在数据里（在 exe 里），所以任何「官方默认键表」都必须
  另外取证（客户端 UI 截图、注册表、或者按键注入实测）。
- **A5** 左右列字段 `left`(90) / `right`(77) / `hide`(40)，用来决定这一项落在设置窗口的左列还是右列。
- **A6** 动作 id 有四个前缀：`I`（通用）、`K`（系统/攻坚特化）、`C`（召唤/骑乘/表情类）、`J`（金币寄售）。
- **A7** 技能槽一共有 12 个：`I21`–`I26`（技能快捷键 1–6）+ `I27`–`I32`（扩展技能快捷键 1–6）；
  消耗品对应 `I33`–`I38`（物品快捷键 1–6）。

## 4. 推断（解释，标注置信度）

- **B1（高）** 「技能栏 12 格」是客户端写死的结构，不是 UI 临时排的：
  动作表里正好是 6+6，且扩展栏 1–7 的截图里出现过第 7 个（`L_Ctrl`），说明扩展栏上限可能是 7 而不是 6。
- **B2（中）** `AradRoyalRumbleCommonType` 是决斗场/大乱斗模式的动作变体，不是独立动作。
- **B3（中）** 默认键在 exe 里，意味着**玩家改键必须由客户端自己持久化**；
  我们的新作把默认值放数据表、玩家覆盖存 user 目录，是同一套思路的更干净版本。

## 5. 与新作设计的关系

- 四类页签 = 可直接照抄的信息架构（已确认项之外，这是**参考实现**，不是设计决定）。
- 123 个动作里有大量「本作不做」的（公会、拍卖行、阿拉德冒险团、决斗场…），
  新作应只保留自己有的系统，其余不出现，避免设置窗口塞满无效项。
- 手柄：`gamepad/gamepadhotkeyinfo.co` 存在，说明客户端手柄映射也是数据驱动的；
  本作先做键盘、手柄留到后续（用户已确认暂缓）。

## 6. 结论与交接

- 已导出 `data/dnf_hotkeys.json`（123 条，含 scope/side/type），本作的键位系统以它为动作目录。
- 临时默认绑定（51/123 已绑）写在 `core/input/dnf_keys.gd`，文档见 `docs/KEYBINDS-HUD-34.md`。
- 交接建议：
  - 新作只保留实际存在的系统动作，别照搬 123 个；
  - 默认键表属于「设计决定」，需要你（设计负责人）拍板，本文只提供 DNF 侧的参考；
  - 若后续要做手柄，我可以再解 `gamepadhotkeyinfo.co` 补一份手柄动作表。
